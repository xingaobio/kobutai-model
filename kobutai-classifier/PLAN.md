# 计划

## 流程

```
采集信号 → 清洗文本 → ①确定性规则 → ②歌手表 → ③小模型 → ④置信度 → 角色池
```

1. **确定性规则**（`config.json` 的 `rules`）：纯音乐站 → music；播客站 → podcast；影视和课程站 → 只能是 video；直播（时长无限）→ 只在 music 和 live 之间选。
2. **歌手表**（`artists.tsv`，2.4 万个名字）：查到的歌手给对应曲风加分，不是硬覆盖，所以"TVアニメ OP"这类标题线索仍能改判。
3. **小模型**（`kobutai.bin`）：字符 n-gram 哈希 + 线性分类，三个输出头（类型 4 类、曲风 10 类、视频 2 类），int8 量化。
4. **置信度**：低于阈值返回 `null`，走通用池。

## 分工

- 主代理：规范、训练和评估代码、推理代码、每轮的错例分析和决策。
- Sonnet 子代理（34 个）：按分片生成歌手名单和带标签样本、写独立验证集、联网抓真实榜单做测试集、给真实标题打标签。
- 脚本：Apple 榜单、B 站热门、YouTube 热门的抓取和转换。
